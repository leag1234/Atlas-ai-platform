# M14 — MCP client and write confirmation

Source: docs/15 §M14 ; REQ-ENG-002/004/009, REQ-FIN-002.

REQ-MCP-001: the harness exposes an optional tool `mcp_call` when an administrator file ATLAS_MCP_CONFIG is configured. Without configuration, the four existing tools remain identical. Strict input: server, tool, arguments (JSON object, maximum 16 KiB). Servers and tools outside the allowed list are rejected before any connection. MCP stdio transport, initialization then tools/call, total timeout 15 seconds, result bounded to 256 KiB, envelope trust=untrusted. Commands and arguments come solely from the administrator configuration, never from the model; no shell. Secrets are referenced by environment variable name, never included in tool declarations or reports. The process receives only the explicitly necessary environment.

REQ-MCP-002: each authorized tool is classified as read or write by the administrator. Server annotations cannot modify this classification. Fixed arguments (notably project_id) are enforced before I/O; their replacement is refused. A write requested by the model makes no provider call: it prepares an immutable action, with a random identifier and a ten-minute duration. The response provides a local URL for previewing the exact arguments.

REQ-MCP-003: only the POST of the human confirmation form can consume a prepared action. GET has no effect; origin and anti-CSRF token are verified. Neither a confirmed argument from the model nor an instruction from the server authorizes the write. An action that is consumed, expired, or whose configuration has changed is refused. Consumption is atomic before I/O; no automatic retry of a write whose outcome is uncertain. PoC UI is single-user local; no public exposure.

REQ-MCP-004: structured local log of server/tool names, status, and duration, without arguments, content, or secrets. Generic provider errors; server stderr is not transmitted to the model. A result containing a configured secret is refused.

AC-MCP-001: real GitLab read via MCP and creation of a synthetic issue after explicit confirmation. AC-MCP-002: zero writes without confirmation, rejection of replay, expiration, and project replacement. AC-MCP-003: no secret leakage in response or log, including from a malicious server. AC-MCP-004: invalid inputs, provider error, huge response, timeout, and unknown tool covered by tests.
