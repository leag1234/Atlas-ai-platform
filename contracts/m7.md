# M7 — Chat and Observability

Requirements: REQ-ENG-004/005/009, REQ-INF-004, REQ-FIN-002; POC-F1..F5,
POC-P6, MISSION M7. Contract published before implementation (R-02).

## Local Public API (port 8020)

- GET /v1/models: OpenAI-compatible list, application alias `atlas`.
- POST /v1/chat/completions: `model: atlas`, `messages` (1..100 objects
  with role system/user/assistant and text content), optional bool `stream`.
  Last user message mandatory; total text <=32000 characters; M6 filter
  validation. Usual client options are tolerated; no tools provided by the
  client are executed. The server maintains POC-P6 budgets.
- Response: id, object chat.completion, created, model, choices (assistant,
  finish_reason), usage (prompt_tokens/completion_tokens/total_tokens).
  In SSE: chat.completion.chunk objects followed by data: [DONE]. Internal
  generation is currently atomic; SSE transports the response after the loop.
- History provided by the client is kept in context; Open WebUI persists
  conversations in its volume. Client cancellation: cancel the bounded loop.
- GET /sources/{chunk_id}: passage cited resolved by the retrieval service; 404
  for a missing source. Rendered citations refer to this path.
- Typed JSON errors without provider details: 400 invalid input, 413 too
  large, 502 provider, 504 timeout/budget; no raw exceptions exposed.

## Internal Boundaries

The gateway accepts an optional bool field `local_enabled` on /agent/complete
(historical default true). The adapter sets this from GPU_LOCAL (default false).
The gateway returns, if requested by `observe: true`, an `observation` containing
provider local/escalade and route simple/complexe. No model name exits this.
GatewayModel accepts this extension without modifying the contract for its old clients.

The retrieval service exposes POST /search {query}: passages with chunk_id, doc_id,
source, text, score (actual reranker score), and GET /sources/{chunk_id}.
Only retrieval reads its database. The adapter uses this contract for rag_search; web
tools and calculation remain those of the harness, with their existing protections.
The model decides tool selection; generation and synthesis pass to the gateway.

## Interaction Log

One JSON line per request, including errors/cancellations, in
BRAIN/interactions/YYYY-MM-DD.jsonl (directory 0700, file 0600).
Fields: timestamp UTC, request_id, question, reponse, modele_utilise
(local/escalade or null before call), route_decision (simple/complexe or null),
latence_ms {retrieval,generation,total}, chunks_recuperes [{chunk_id,doc_id,score}],
citations [{chunk_id,doc_id,source,text}], tokens {in,out}, cout_eur,
erreurs (codes), state. Conservative reserved cost kept in case of unknown usage;
received tokens are separated from this reservation. Injected secrets and key
patterns are masked in the entire line; no headers recorded.

## Startup and Validation

make serve starts CPU gateway, PostgreSQL/pgvector index, retrieval HTTP,
adapter, and real Open WebUI container. No GPU provisioned; GPU_LOCAL=1
only allows using an already configured local endpoint.
Ports bound to 127.0.0.1; user access via SSH tunnel to 3000; API accessible
to Open WebUI via Linux host network. Persistent volumes; stops processes and
containers launched by the command, without deleting data.

make test-ui: integrated HTTP test with recorded provider responses, real
citation resolution, log inspected, no paid CI calls. Real Open WebUI
is started for verify-m7 and remains reachable until the final protected check.
Negative tests: empty/huge/Unicode input, unavailable provider, timeout,
invented source, secret in question/response, streaming, history, and budget.
The protected workflow invokes make test; scripts/test.sh can call verify-m7.
