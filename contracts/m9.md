# M9 — projects, conversations and fact memory

Source: docs/15 M9 ; REQ-ENG-002/004/005/007/009, REQ-FIN-002, POC-P6.
Separate contract before implementation, without modification of protected verifiers.

## Storage and scope

Retrieval has a new local storage under BRAIN/projects.sqlite (0700 for
the directory, 0600 for the file). It groups projects, conversations, documents,
instructions and facts. No direct access from the orchestrator to this storage.
Data remains local, ignored by Git, without export in reports.
The M2 corpus remains independent; a query with a project consults only that project.
No migration or deletion of existing M2/M7 data.

Project/conversation/document/fact identifiers are UUIDs created by the server.
Each child access verifies the parent in the SQL query. Project citations
are never resolved by the global M7 route. Unknown IDs or those belonging to
another project produce 404, with no content or provider detail.
The PoC is single-user on loopback; a project ID is a logical scope,
not a multi-user authorization. No additional public access.

## Retrieval API, prefix /projects

- POST /projects {name, instructions?} : creates a project; GET /projects : list.
- GET /projects/{p} : project; PATCH same path {name, instructions} : replaces.
- POST /projects/{p}/conversations {name} : creates a conversation.
- GET /projects/{p}/conversations : list; GET /projects/{p}/conversations/{c} :
  persisted exchanges. A conversation does not change project.
- POST /projects/{p}/documents {name, text, lang} : textual document split with
  the existing pipeline and indexed via embeddings gateway; GET same path : list.
  Existing document formats remain managed by their M2 extractor.
- POST /projects/{p}/search {query} : hybrid ranking M2 exclusively on
  project chunks; GET /projects/{p}/sources/{chunk_id} : scoped resolution.
- GET /projects/{p}/facts : inspectable facts (id, text, conversation_id).
- PATCH /projects/{p}/facts/{f} {text} : priority user correction.
- DELETE /projects/{p}/facts/{f} : individual erasure; DELETE /projects/{p}/facts :
  total erasure. Archived conversations are never used to re-extract erased
  facts. A revision counter invalidates ongoing consolidations during
  a correction or erasure (no resurrection at the end of a request).
- POST /projects/{p}/context {conversation_id, query} : instructions, relevant facts
  identified as memory, revision and history of this conversation.
- POST /projects/{p}/turns {conversation_id, question, answer, facts, revision} :
  atomic recording of the exchange; new facts only if the revision
  is still current. Facts extracted only from the new user message.

Validated inputs: name 1..120 characters, instructions <=4000, document <=32000,
question/answer <=32000, fact 1..500, <=8 proposed facts per turn. Identifiers
validated; parameterized SQL. Bounded HTTP body. Typed errors without confidential text.

## Adapter and interface

POST /v1/chat/completions accepts project_id and conversation_id together or neither.
In project mode, the server loads the associated history; the client cannot inject
history from another project. The last user message remains the question.
Relevant facts are separated from instructions and documentary sources.
The result explicitly distinguishes memory and documentary citations.
Automatic consolidation uses the existing gateway: no provider SDK,
model name, hard-coded prompt outside authorized directories. Facts are not a
raw summary nor a copy of the history. Corrections/erasures are not
undone by late extraction. Old exchanges remain inspectable,
but do not reintroduce a deleted fact into future context.

Basic local interface on the adapter: project and conversation selection/creation,
instructions/documentary notes, visible, modifiable and erasable facts, chat using these IDs. HTML escaped, rendered by textContent, no scripts drawn from user content. Open WebUI M7 remains available.

## Budgets, proofs and implementation order

Global budget per request including consolidation <=0.05 EUR, <=120 s; reservation
before each call. No GPU created, added infra cost 0 EUR/h. Provider network
only via gateway; private memory not sent to the web search engine.
Tests use only synthetic inputs and cassettes dedicated to tests.
BRAIN/eval/memory.json report contains booleans calculated from real assertions
: fact_reused_across_conversations, projects_isolated, erasure_effective,
memory_vs_source_distinguished ; no user content.

Tests: persistence after reopening; conversation from wrong project; search
and citation from another project; fact erased/corrected during request; malformed
extraction, timeout, budget and provider return; HTML injection; memory/source;
requests without project M7 unchanged. make test-memory then make verify-m9 execute
these controls. Existing CI calls the gate via scripts/test.sh, without modification
of the workflow. CI for the contract alone does not prove completion of M9.
