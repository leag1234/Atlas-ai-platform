# M19 — explicit intent and language

Source: MISSION M19 D1–D4/J15–J20; REQ-ENG-004/009/011,
REQ-FIN-002, POC-F1/F5/P6. Extends the merged M18 contract.

The chat model receives a `generate_image` function with one required string
`prompt` (nonblank, at most 2000 characters, no extra arguments). The model
chooses generation; lexical hints cannot exclude natural generation requests.
Uploaded-image analysis and unsupported pixel editing retain their vision path.
Capability questions receive an affirmative explanation, without generation.

Image execution uses the same request deadline and EUR 0.05 ledger as the
model's decision and prior tools. Reserve before execution and fail closed when
remaining time or money is insufficient. Successful generation ends the turn
with a stored image reference; do not send image bytes back to the text model.
Project requests use only validated project history; no cross-project context.

Resolve language from the current message, inheriting the conversation language
for messages shorter than five words. Without usable history, detect the current
message, then use the UI locale. Recognize uppercase and unaccented French.
Carry the resolved language explicitly into each user-facing model prompt,
including vision, web and transformations. Explicit translation targets override
conversation language for translated content. Image rewrite uses English for the
worker and preserves the source language and all constraints in its instruction.
Status strings remain fixed resources selected by UI locale.

The system prompt declares retrieval/citations, web search/reading, calculation,
vision, image generation, project memory and confirmed MCP tools. Failures name
the failing operation, without denying a supported capability.

Standard tests lock these capabilities, language instructions, 180 CI polls,
512 image sequence tokens, 1024-square images, variable seed, watchdog at least
180 seconds and the gateway's existing image model/license. Public API journeys
J15–J20 extend J1–J14, with real recorded provider exchanges for deterministic CI.
No protected verifier, workflow or CODEOWNERS changes are permitted.

Implementation plan: language resolver and versioned prompts; chat tool and shared
image budget; gateway vision/rewrite prompts; project routing; settings locks and
public journeys; Makefile/test runner integration; measured report. No dependency
or infrastructure changes are planned. Local verification precedes the final PR;
only a green `ci` job authorizes squash. Provisioned GPU resources are removed
at session end within the owner's EUR 2/hour and EUR 30/milestone ceilings.

The language increment centralizes instructions in `prompts/language.json` and
resolves project language only after rebuilding validated project history. Web
excerpt selection must preserve an explicit `web_fetch.query` supplied by the model.
The exact French journey inputs live in `tests/journeys/m19-cases.json`; MISSION
uses linked English glosses to satisfy the unchanged public-documentation gate.

The internal image request accepts `max_cost_eur` (positive, at most 0.05),
`timeout` (positive, at most 120 seconds), and the resolved `lang`. The chat caller
deducts the model ledger before supplying these limits. Rewrite reservation must
fit the remainder before any paid rewrite call. A selected image ends the tool
loop; image bytes never enter another text-model turn.

GPU selection checks the hourly ceiling before choosing a type. If the affordable
preferred type is reported unavailable, a bounded creation attempt may confirm
capacity; an available but more expensive type must never replace it.

The image worker offloads sequentially to CPU when usable GPU memory is below
40 GiB; larger GPUs retain CUDA placement. This preserves the locked image
settings on the affordable L4 without changing the per-request cost ceiling.

The September 15 timeout addendum caps HTTP connections at 5 seconds, search
at 15 seconds, and page reading (including robots and redirects) at 30 seconds.
Each is bounded by the caller remaining deadline; the overall 120-second request
budget remains enforced. This explicitly relaxes the PoC 15-second page limit.
Journey reports identify live/replay evidence per journey; J8 remains a separate
service restart check. No new external API or schema is introduced.
