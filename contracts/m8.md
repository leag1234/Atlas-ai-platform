# M8 — Task-based serverless routing

Source: docs/15 M8, REQ-INF-004, REQ-MOD-004, REQ-ENG-004/006/009,
REQ-FIN-002, POC-P6. Separate contract prior to implementation (docs/11 R-02).

## Configuration and compatibility

The gateway is the sole owner of model identifiers, capabilities, and rates.
Serverless configuration for text, code, vision, and embeddings; Scaleway provider
only, HTTPS endpoint, secret injected via environment.
The generalist model remains configurable via ESCALATION_MODEL; specialized
models are configurable within the gateway. No GPU provisioning or calls by default.
Explicitly local M4 clients retain their historical contract;
M7 requests with local_enabled=false use task-type-based selection.
Simple/complex ranking remains available for metrics compatibility.

## Decision and transport

Pure message classification: image presence takes priority, then programming
request, otherwise text. System instructions and tool responses must not
reclassify a conversation on their own; preserve user context.
Multimodal messages are not flattened into text by the gateway.
Support for public upload and progressive display in the UI remains M12/M11.

POST /agent/complete preserves the M3/M7 envelope; observation may add
task_type (text/code/vision) and fallback bool, without model identifier.
POST /agent/config provides a rate bound covering all possible paths,
including the switch, for conservative reservation in the POC-P6 harness.
A single serverless switch on primary error/timeout, within the initial deadline;
no blind retry after budget exhaustion nor return of simulated data.
Vision switches only to a model capable of receiving images.
Tokens, costs, and decisions are observable without text or secrets in logs.
Unknown costs in case of failure remain reserved; no path exceeds
0.05 EUR/request. Missing prices and context overruns fail before calling.

## Verifications

make test-serverless writes BRAIN/eval/serverless.json from call
observations: text_task_served, code_task_served, function_calling_ok,
streaming_ok and fallback_ok, as well as vision, embeddings, capabilities/context,
tokens, costs, and duration. Booleans are not manual success markers.
Probes use only public and synthetic test inputs, never BRAIN/interactions. A real
failure is reported as such.
Provider streaming verifies multiple SSE events and a termination;
function-calling verifies the name and structured arguments of the expected tool.
The fallback injects a failure only in the test harness.

CI tests without paid calls: text/code/vision classification, Unicode, empty,
giant input, missing rate, deadline, primary error and double failure,
message preservation, compatible envelope, and conservative budget.
Real responses recorded under tests/ for transport tests, without secrets.
make verify-m8 calls the protected verifier; scripts/test.sh connects it
to the existing ci job with static mode and explicit replay tests.

No protected file modified; no new dependencies planned.

with individual cap of 0.05 EUR and stop after three provider failures.
