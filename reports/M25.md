## 5. The dominant failure mode is fabricated precision

H10 in the held-out set scores 2 / 0 / 3 across the three profiles, the only case where
all three collapse together. The judge's reasons:

- glm invents a LINE button on the Warm Audio WA73
- deepseek invents a variable 300 Hz high-pass filter on the same preamp
- qwen states a false physical explanation and prescribes a flawed gain-staging procedure

Same defect as J51, different domain, on cases the agent has never read. Fabricated
precision is not an incident; it is the dominant failure mode. It is coherent with the
disposition: M25 asks for precise, named, dated things, the model complies, and with no
verification mechanism it produces invented precision. H10 alone pulls atlas-qwen's
held-out mean from 8.1 to 7.3.

The mechanical rule "no URL that was not retrieved" would not have caught H10: no source
is cited there. Both a retrieval constraint and a behavioural one are needed.

## 6. What the gates could not see, and why

tests/m25_gate.py sets M25_REPLAY=1 and writes mode="replay" into the report; the
verify-m25.sh gate accepts either mode. No gate in this milestone can require live
execution. Everything in sections 3 and 5 was found by running live and checking the facts
by hand.

This is the third instance of the same class of defect (M24 declared PPTX delivery working
and it failed in front of the owner the next day). It is what M26 D1 exists to fix.

## 7. Carried forward

1. M26 D1: live acceptance as the only acceptance; a gate must be able to demand it.
2. M26 D5: a source is cited only if it was retrieved; a stated specification of a named
   product is either verified or declared as recalled from memory; an open design question

3. A budget refusal must report what was measured, not masquerade as HTTP 504.
4. deepseek's regression: model-specific prompt work, or drop the profile. Open.
5. glm's -1.36 off-corpus: watch at the next milestone, sample too small to settle.
